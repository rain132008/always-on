# 当前设计决策

整体范围沿用 [v0.7 设计稿](../SDD_Always_on_MVP_AEE8A196E688_v0.7_88E9B6AEE5808FE5BABA%25BF.md)，P2 和 P3 在外部阶段使用 Mock Connector 和合成数据。

## Run 恢复和工作区

- Session 绑定工作区的规范化绝对路径和文件系统目录身份。派发时与发出执行上下文前核验；发现原目录缺失或被替换时，保留待办回复与 Wakeup，进入 `recovery_required`。
- 每个 Session 有单调递增的执行代次。Run 记录代次、PID、进程创建时间、工作区和恢复会话 ID。子进程在此记录提交前等待上下文。完成事务核对任务、Run、代次、已领取 Wakeup 和 Session ID。
- 服务重启时核对未结束的 Run 并转为 `recovery_required`。MVP 对这些 Run 统一要求人工重新排队。只在确认旧进程退出、PID 已被复用，或确认执行上下文尚未释放时允许继续。工作区仍需匹配。
- Mock Agent 从 SDD 根目录启动，单 Dispatcher 串行执行。真实写入隔离、任务独立工作区和真实 Claude 进程树停止由内网适配负责。
- Claude CLI 专用验收入口使用独立的合成工作区、会话存储和 SQLite，并显式禁用工具、MCP 和项目指令加载。Runner 从 CLI 返回值取真实 Session ID，再用自身的任务 ID、Run ID 和代次构建可信结果。模型仅生成状态、摘要和待办问题。
- 会话名称保存在 Session，历史数据默认显示关联任务名。手动继续仅接受已有外部 Session ID、处于完成或失败状态且工作流启用的任务。提交时校验原工作区，记录 `manual_resume` 并通过同一队列和 Run 代次执行。人工追问采用原事件快照，跳过该快照的自动发布动作。
- 手动关闭将 Task 置为终态 `closed`，同一事务取消待执行 Wakeup 并记录原因。已领取但尚未启动的运行也取消。已开始的轮次可以收尾，其晚到结果只结束本轮，无法创建新待办、产出或 Outbox 动作。重启后的残留进程可在原任务中停止。相同主题的新事件会继续推进来源游标，已关闭任务不会重新入队。
- Agent 可在报告中选择延期续跑或请求人工澄清。延期从结果入库计时，Wakeup 和 Run 结果在同一个事务提交，预约键绑定 Run ID。任务等待到期时状态为 `waiting_timer`，后续在原 Session 运行。新主题版本会取代旧预约。工作流停用门禁在领取与 Agent 启动登记时核验，已到期的预约在启用后执行。连续自动唤醒计数存于 Wakeup。

## Outbox

待办、Run 结果及 Mock 通知入队共享事务。Outbox 在调用 Connector 之前提交 `sending`，中断或结果未知时转为 `reconciling`。Connector 只有确认远端未接收，才允许退避重试。查到远端记录则登记其 ID。无法核对进入 `needs_reconcile`，管理台可记录核对证据及结论。真实 MR 外部动作使用 `provider / project_id / mr_iid / head_sha / skill_hash` 生成稳定业务键，未来 Connector 需能用它定位远端记录。

## 工作流与扫描

- YAML 绑定 Trigger、Source、Condition、Agent Profile、Skill ID/版本、Session Policy 和结果动作。服务启动时做 Schema 与注册表校验。每条入队事件持久化有效配置摘要及输入，人工回复继承产生待办的事件快照。YAML 决定加载哪些定义，管理台启停单独持久化在 SQLite。停用后不再接受新触发或领取队列，已领取 Run 可以收尾。重新启用后继续已入队工作，并从原游标补扫。
- Poll 与带 IANA 时区的五段 Cron 共用 Dispatcher。重启时扫描最新的到期时段，用已存游标追踪停机期间积累的增量。手动扫描使用同一条入库链路，定时检查点由定时触发更新。
- 管理台展示启动时有效的 YAML 和最近 50 条 Task Run、50 条扫描记录。源扫描保留最近 100 条有变化、手动触发或失败的记录。失败原因使用可展示的概要，完整异常留在服务日志。
- 单个源批次的游标与 Task、Event、Wakeup 一起提交。入库失败时整批回滚，下轮可按原游标重扫。已提交的澄清待办和独立 Session 持久保留，后续仓库扫描可以继续收取增量。
- MR 按平台、项目、编号复用 Session，同一工作流中同一 SHA 去重。扫描以 Connector 查询到的当前 head 为准，合并尚未领取的连续版本。提交同主题 Run 结果前补查来源，新版本已入队时保留 Session 并将本轮标为 `superseded`。恢复中断的旧 Wakeup 时，已有新版本即只处理新版本。评论发送前最终核对 head 和状态，过期动作记录为 `superseded`。每条评论的业务键包含 Skill ID 与版本。
- 文档提交按仓库、分支、SHA 生成任务，Mock 分析请求澄清，回复触发同一 Session。完成结果作为 `document_suggestion` 产出保存到任务记录。

## Agent 管理与工作流绑定

- Agent 目录内置通用任务、代码评审与文档维护三个配置。管理台可新增和修改名称、职责说明、任务提示词，并为每个工作流选定一个执行 Agent。目录及页面绑定存储在 SQLite，未单独设置的工作流沿用 YAML Profile 对应的默认 Agent。
- 工作流 Profile 决定输入输出协议，Skill 版本和结果动作也归工作流 YAML。执行 Agent 决定真实 CLI 接收的额外任务提示词。Mock 按工作流协议模拟结果。
- 新触发以入队时的 Agent ID、名称和任务提示词生成事件快照。人工回复、延期续跑、重试与手动继续沿用原事件快照。Run 写入选定的 Agent ID 和名称供历史查询。发布此功能前的历史 Run 可能没有 Agent 记录。
- 本机可通过启动配置仅将新 SDD 任务交给 Claude Code `2.1.109`，Git 来源及其所有 Run 继续走 Mock。执行方式随事件快照入队并记录至 Run，人工回复、预约和手动恢复继承原 Runner。本机早期的无 Runner 快照按 Mock 恢复，独立 Claude 验收数据库中的旧快照仍按 Claude 恢复。指定 Runner 不可用时进入待恢复，不跨后端续跑。

## Web 工作台

- 桌面工作区最大宽度为 1520px。任务大厅是独立页面，使用状态和工作流筛选、搜索和任务卡片。默认依次突出待人工、运行中、异常和最近三天完成的任务。列表 API 提供只读的最近轮次摘要、待回复问题和下次自动唤醒时间。
- 任务详情按真实时间展示用户指令、执行结果、人工问答、系统事件和关联产出，结果保留完整文字和代码块。活动流直接接收人工回复或新指令，调用现有 API 继续原会话。上下文区展示触发来源、等待条件、下次唤醒、会话和产出入口。
- 运行日志、完整触发信息、工作区和标识可以展开。当前 Runner 提供已保存的运行结果、产物和日志，工具调用记录与逐 token 输出取决于后续 Runner 数据能力。会话、工作流、Agent 和外部动作共用导航、状态标签和表单样式。
- 核验重排、回复、手动 Resume 和关闭继续使用现有状态规则。停用工作流会阻止新的继续操作，已关闭任务停留在历史视图。
- 界面以暖白、深绿和中性边框区分阅读区与可执行操作。待回复的任务在标题下直接展示当前问题和答复入口，历史中保留对应轮次。预约任务在同一位置展示下次唤醒。正文限制行宽，长结果保持完整阅读。
